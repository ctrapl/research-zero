# Phase 0 澄清脚本

## 为什么要做这一步

用户的第一句话几乎从来不是研究问题：

- "我想做 AI 医疗" —— 这是领域名，装着影像诊断、药物发现、电子病历、蛋白结构，检索式完全不同。
- "导师让我找个方向" —— 连学科边界都没给，可能意味着导师有隐含偏好。
- "我对大模型感兴趣" —— 这是技术兴趣，不是研究问题。

直接拿这些去检索，命中动辄几万篇，排序会退化成"高被引论文列表"，跟用户的实际处境毫无关系。**澄清 3 分钟，省掉后面全部返工。**

## 四个必问项

用结构化选项提问，不要开放式。开放式的回答通常还是一句模糊的话。

### 1. 阶段与学科背景

> 你现在处于哪个阶段？

- 本科毕设（3–6 个月，要求可完成，不要求创新突破）
- 硕士开题（1–2 年，要求有新意、能发表）
- 博士开题（3–5 年，要求撑起完整工作）
- 跨领域转行 / 自学（无固定期限，先能读懂文献）
- 课程论文 / 竞赛项目（周期短，要求可交付）

同一份清单，博士需要 40 篇前沿纵深，本科毕设只要 15 篇能上手复现。**这一项直接决定清单规模。**

### 2. 可用资源

> 你目前手上有什么？（可多选）

- 有可用的数据集 / 队列 / 临床样本
- 有算力（GPU / 集群）
- 有实验设备 / 湿实验条件
- 只有一台笔记本
- 导师已有成熟方向，可以跟着做
- 完全从零开始，没有任何资源

资源决定哪些"空白"对用户是可做的。没有湿实验条件的本科生，指向细胞实验的空白毫无意义。

### 3. 时间预算

- 3 个月内（毕设中期 / 课程论文）
- 半年
- 1–2 年（硕士）
- 3 年以上（博士）

### 4. 偏好倾向

- 偏理论：证明、建模、算法性质分析
- 偏工程：系统实现、性能优化、工具链
- 偏应用：落地场景、真实数据、效果验证
- 偏综述：文献梳理、体系构建、benchmark
- 还不确定，先看看这个领域有什么

## 学科追问（按模板追加 1 问）

### 医学 / 生医

> 你的问题里，疾病/干预的英文标准名称是什么？导师有没有要求必须纳入指南或共识？

- 需要 2–3 个 MeSH 主题词（PubMed 页面右侧 "MeSH terms"）
- 明确是否包含临床指南、系统综述、RCT（决定证据等级加权）
- 是否有人群/年龄段/随访时长限制

没有 MeSH 词的医学检索，精度会明显下降；报告里要写明"未提供 MeSH 词，精度有限"。

### 计算机 / AI / 通信

> 你更认哪个学术共同体？有没有目标会议/期刊？

- 目标会议（NeurIPS / CVPR / ACL / ICC / INFOCOM…）决定"必读"的判定
- 是否接受 arXiv 预印本作为主要来源
- 有没有代码/数据可得性要求

### 跨领域

> 你的原专业是什么？想在哪个领域立足？

转行者的最大优势是原领域视角，最有价值的选题常是"A 领域方法解决 B 领域问题"。要主动挖这层，并准备两轮检索。

## 按阶段调整问法

**本科毕设**：重点问"能不能复现""导师有没有基础代码"。这类用户最需要"3 个月能做完的最小可行课题"，而不是前沿方向。

**硕士开题**：重点问"导师方向""有没有前期积累"。国内硕士开题的现实约束是导师课题；理想方向跟导师不搭，基本做不成。主动问一句"导师希望你往哪个方向靠"。

**博士开题**：重点问"你想在哪个学术共同体里立足"。博士选题等于选未来五年的同行圈子，要问清目标会议/期刊。

**跨领域转行**：重点问"你的原专业是什么"，并准备两轮检索。

## 用户直接给论文时

不要跳过澄清，也不要只总结这几篇。处理顺序：

1. 读这几篇的标题、摘要、关键词、作者单位
2. 反推所属子领域与相邻方向："这几篇都在做 X 的 Y 问题，属于 Z 子领域"
3. 用这几篇的标题词构造 `focus`，用更宽的上位词构造 `broad`
4. 做领域级检索，在方向卡里写明"起点论文"与"由它扩散出的子领域"

**输入边界**：只接受标题、DOI、arXiv ID、摘要文本。用户发 PDF 时不解析全文，先请对方给出标题或 DOI；PDF 里的结论不能当作"本次已核验"的事实写进报告。
5. 交付时说明："你给的 3 篇是起点，这个领域还有 N 篇必读，按这个顺序读"

只总结单篇论文等于没解决用户"从零进入领域"的问题。

## 方向确认卡模板

澄清完成后输出这张卡，等用户确认：

```
## 方向确认

**研究问题**：<一句话，包含"在什么场景下、解决什么问题、用什么思路">
**范围边界**
  - 做什么：<3 条>
  - 不做什么：<2～3 条，明确排除容易混淆的相邻方向>
**所属子领域**：<细分领域名，不是大领域名>
**学科模板**：<general / cs / medicine>，数据源 <...>
**关键词簇**
  - 英文：<4～6 组，每组含近义词>
  - 中文：<3～5 个>
**检索约束**：<MeSH / arXiv 分类码 / 目标会议>
**约束条件**：<时间 / 资源 / 导师方向>
**起点论文**（仅论文入口时填写）：<标题 + 年份>

确认这个方向对吗？需要调整哪部分？
```

## 追问策略

用户回答含糊时（"都行""看情况"），不要接受模糊答案，也不要连珠炮提问。用一句具体对比把选择逼出来：

- "都可以" → "如果只能选一个，你更想三个月后交一份能跑的代码，还是一份讲得清的综述？"
- "不知道导师要什么" → "导师最近在做什么课题？有没有让你读过哪篇论文？"
- "想做热点" → "热点有两种：已经挤满人的（通用大模型微调），和刚起来还没挤满的（某个垂直场景）。你要哪种？"

## 什么时候可以跳过

只有同时满足以下三条才跳过澄清：

1. 用户已给出明确研究问题（不是领域名）
2. 已说明阶段和时间预算
3. 已说明约束（资源或导师方向）

缺一条就补问。跳过省下的时间，会在用户说"这不是我要的"时全部还回去。
