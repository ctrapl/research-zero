# 开题素材包（Proposal Kit）

`scripts/export_proposal.py` 把 `plan.json` + 已回验的 `refs_verified.json` 变成一套可直接改的开题素材。**它不是开题报告定稿**，而是把"已有证据的部分"写好、把"必须由用户补的部分"留成显式的待补标记。

## 目录结构

```
开题素材/
├── 00_开题速览.md          一页纸，给导师快速判断值不值得做
├── 01_研究背景与意义.md    问题从哪来、为什么现在值得做
├── 02_国内外研究现状.md    按主线组织，带文献与引用
├── 03_研究内容与技术路线.md 研究内容、方法族选择、阶段计划
├── 04_创新点候选与风险.md  来自"疑似空白"，全部标注未验证
├── 05_答辩预演.md          导师/评委最可能问的 10 个问题与证据边界
├── 06_参考文献.bib         与报告同一批文献，导入 Zotero / EndNote
└── README.md              使用说明与待补清单
```

## 写作硬规则

1. **文献只能来自 `records`**。脚本导出时只认 `ref_key`，不认手写标题。导出的每一处 `（作者, 年份）` 都来自检索记录。

2. **不把推测写成结论**。"疑似空白"在素材里固定写成：

   ```
   【待验证】本次检索（N 篇，范围 X）未见……
   需要核实：……
   ```

   不得改写成"该方向尚属空白"。

3. **未回验的文献不进素材**。`export_proposal.py` 读的是 `build_report.py` 输出后的 `refs_verified.json`（或带 `doi_verification` 的 `refs_ranked.json`）；`link_only` 放行并标注"无 DOI，按链接回溯"，`mismatch` / `not_found` / `no_doi`（无链接）/ `error` 剔除。

4. **待补项要具体**。不写"补充实验"，写"需要补：3 家医院 2023–2025 的 XX 影像数据，伦理批件编号待定"。空泛的待补项等于没留。

5. **不伪造用户信息**。导师姓名、单位、伦理批件号、基金号一律不写；需要时留 `【待填：导师姓名】`。

## 各文件写作要点

### 00_开题速览

- 研究问题一句话（来自方向卡）
- 为什么是现在（3 条，每条挂文献）
- 打算怎么做（路线表里的 1–2 个方法族，不铺开）
- 预期产出与最小可行结果
- 最大风险与退路

导师看这一页就决定要不要往下看。**不超过 800 字**。

### 01_研究背景与意义

结构：领域现状 → 未解决问题 → 本研究切入点。每段结尾必须有文献或明确标注"本节为领域常识，未逐条引用"。禁止写"随着人工智能的快速发展"这类无信息量的开头。

### 02_国内外研究现状

按报告里的 3–5 条主线组织，不要按年份流水账。每条主线：起点（代表文献）→ 关键跃迁（为什么转向）→ 当前 SOTA → 这条线还没解决什么。国内外差异只在有证据时写，没有证据就写"本次检索未区分国别来源"。

### 03_研究内容与技术路线

- 研究内容拆 2–4 个课题，每个课题对应一条方法族或一个空白候选
- 技术路线用表格：阶段 / 输入 / 方法 / 输出 / 验收标准
- 阶段计划按 `time_budget` 自动折算周数，但用户要复核（开题周期常被低估）
- 每个阶段必须写"失败时的退路"

### 04_创新点候选与风险

创新点只能来自两类证据：

- 空白候选（标注【待验证】+ 检索范围）
- 方法迁移（A 领域方法用于 B 领域，且两边都有文献支撑）

每条写：创新点表述 / 支撑证据 / 撞车风险 / 验证方式。**没有撞车风险分析的创新点不要写进开题报告。**

### 05_答辩预演

固定覆盖 10 个高频问题：为什么选这个题、为什么不用 XX 方法、数据和伦理从哪来、工作量够不够、创新点在哪、和 XX 的工作有什么区别、做不出来怎么办、时间怎么排、评价指标是什么、结果不显著怎么办。

每个答案必须落到"报告里已有的证据"或"明确的待补项"，不要写漂亮话。

### 06_参考文献.bib

与报告同一批文献，`link_only` 的 arXiv 条目带 `eprint` 字段。导入后先检查年份与作者，再用于正式文档。

## 何时不该导出

- plan 没填完（validate 不通过）——脚本会直接中止导出，不要用 `--force` 绕过；素材缺主线或路线，等于把半成品交给导师
- DOI 回验未做且用户明确要求正式材料——先跑回验
- 用户还没确认方向卡——先回 Phase 0
