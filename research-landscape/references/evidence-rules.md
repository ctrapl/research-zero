# 证据规则判例

三条规则在 SKILL.md 里只写了一句话，这里给具体判例。拿不准时以本文件为准。

## 规则一：文献条目只能来自脚本

### 反例（全部禁止）

```
❌ "该领域的奠基工作包括 LeCun 1998 年的 LeNet 和 Krizhevsky 2012 年的 AlexNet。"
   —— 可能确实存在，但没经过本次检索，属于凭记忆作答。
```

```
❌ "另外建议阅读 Goodfellow 的 Deep Learning 一书。"
   —— "另外建议"是绕过检索最常见的口子。要加就必须让脚本搜到。
```

```
❌ 报告里出现 DOI 但脚本返回中无此 DOI。
   —— 用户一查就穿帮，整份报告报废。
```

### 正例

```
✅ 需要补一篇脚本没搜到的经典文献时：
   "脚本以当前检索式未命中 XX（1998）的工作，若需要可自行用标题关键词
    'gradient-based learning applied to document recognition' 核实。"
```

### 边界情况

| 情况 | 处理 |
|---|---|
| 用户点名要某篇论文 | 用标题去脚本里搜一次；搜不到就说明搜不到，不编元数据 |
| 脚本只返回标题没有摘要 | 可以用标题判断，但不要编写内容描述 |
| 同一篇的预印本 + 正式版 | 保留正式版，预印本标注"已被 XX 接收"；脚本按标题合并 |
| 用户给的 PDF 与检索结果冲突 | 以用户提供的原文为准，但要说明"该文未进入本次检索清单" |

## 规则二：每条文献必须可回溯

渲染前强制执行回验，口径：

- 有 DOI → Crossref 核对标题/年份/第一作者
- 无 DOI 但有 arXiv / PubMed / landing page → `link_only`，报告中注明"按链接回溯"
- 三者都没有 → **剔除**，不留占位

判定：

| 状态 | 是否进报告 | 报告中的写法 |
|---|---|---|
| verified | 是 | 正常引用 |
| partial | 是 | 标注"部分字段与 Crossref 不一致" |
| link_only | 是 | 标注"无 DOI，按链接回溯" |
| mismatch / not_found | 否 | 终端列出，报告不提 |
| no_doi（无链接） | 否 | 同上 |
| error（网络） | 否 | 同上，并建议网络恢复后重跑 |

DOI 格式规范化：必须是 `10.xxxx/...`；去掉 `doi:` 前缀、`https://doi.org/` 前缀、首尾空格与标点。

## 规则三：区分事实与推测

这是最容易被违反的一条，因为没有硬性检测手段。

### 事实的写法

```
✅ "GNN 在分子性质预测上的代表性工作是 MPNN（Duvenaud et al., 2015）与
   D-MPNN（Yang et al., 2019），后者在 12 个 MoleculeNet 任务上报告了
   平均 6% 的误差下降。"
```

判据：每个断言都能指向一篇具体文献的摘要或结论。

### 推测的写法

推测可以写，但必须**带限定词和依据**：

```
✅ "在本次检索的 62 篇记录中，未见将 diffusion model 用于晶格缺陷预测的工作。
   这可能是空白，也可能是检索词未覆盖（diffusion 在材料领域常表述为
   'generative model'）——建议用后一组关键词复核。"
```

```
❌ "diffusion model 在晶格缺陷预测上尚属空白，这是一个很好的切入点。"
```

### 三级置信度

| 级别 | 判据 | 写法 |
|---|---|---|
| **证据充分** | ≥2 篇独立文献支持 | 可直接陈述 |
| **单一来源** | 只有 1 篇提到 | "据 X（2024）报告……" |
| **推测** | 无文献支持，基于检索缺席推断 | "本次检索未见……，可能是空白，需进一步核实" |

报告第七节"疑似研究空白"**默认全部按第三级写**。任何看起来像结论的表述都会误导用户。

## 开题素材包的特殊规则

素材包比报告更接近"正式材料"，因此额外要求：

1. **每条引用必须能对上 records**。`export_proposal.py` 只认 `ref_key`，plan 引用了被回验剔除的文献会直接中止导出。
2. **【待验证】【待补】【待填】不能悄悄删**。这些标记是给用户的任务清单；删掉标记等于伪造完成度。
3. **创新点必须带撞车风险**。只写"没人做过"没有价值，要写"最像的 2–3 篇工作是什么、差异在哪"。
4. **不伪造用户信息**。导师姓名、单位、伦理批件号、基金号一律留空。
5. **时间计划要能落地**。按 `time_budget` 折算周数只是起点，用户必须按实际开题节点复核。

## 引用格式

报告内统一作者-年份行内引用，不用脚注编号：

```
（Duvenaud et al., 2015）
（Yang et al., 2019, NeurIPS）
```

中文作者用全名（张三，2024），不要只取最后一个字。同一作者同年多篇用 2019a / 2019b。

## 自检流程

渲染前按顺序走：

1. **链接校验**：`build_report.py` 自动跑；报错就补 DOI 或删条目
2. **回验校验**：未通过的条目是否已从正文、近期、附录三处一并移除
3. **"为什么必读"校验**：脚本只查非空，"是否具体"要人判断；"很重要""经典之作"重写
4. **无主语句扫描**：搜"出现了新方法""取得了突破""受到广泛关注"
5. **推测标注扫描**：搜"空白""尚未""首次""无人"，逐条确认有依据或限定词
6. **边界声明**：报告末尾写了数据源、年份范围、覆盖边界

## 一个自检用的提问

> 如果我是用户的导师，看到这份东西，会问哪三个问题？

通常是：为什么选这几篇、这个空白你怎么知道没人做、这个方向三年做得完吗。把它们补进报告对应位置。
